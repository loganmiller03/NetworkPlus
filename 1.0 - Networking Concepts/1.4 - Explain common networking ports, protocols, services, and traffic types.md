# 1.4 - Explain common networking ports, protocols, services, and traffic types

### Introduction to IP
* a series of moving vans
  * efficiently move large amounts of data
    * use a shipping truck
  * the network topology is the road
    * Ethernet, DSL, cable system
  * the truck is the IP
    * we've designed the roads for this truck
  * the boxes hold your data
    * boxes of TCP and UDP
  * inside the boxes are more things like application information
* TCP and UDP
  * transported inside of IP, encapsulated by the IP protocol
  * 2 ways to move data from place to place
  * OSI layer 4 - transport layer
  * multiplexing - use many different applications at the same time
* TCP: Transmission Control Protocol/2
  * connection oriented: a formal setup and close, TCP data always gets an ACK message from receiver
  * reliable delivery: recovery from errors. can manage out of order messages or retransmissions
  * flow control: receiver can manage how much data is sent
* UDP: User Datagram Protocol
  * connectionless: no former open/close, receiver does not send any ACK)
  * unreliable delivery: no error recovery, no reordering of data or retransmissions
  * no flow control
* Speedy delivery
  * the IP delivery truck delivers from one IP to another, every computer(house) has an IP(address)
  * boxes arrive at IP, where do they go now?
    * each box has a room name (port number) on the outside
    * each room is expecting the correct box i.e. each port is configured to receive the correct TCP/UDP data
* lots of ports
  * IPv4 sockets
    * server IP, protocol, server application port number
    * client IP, protocol, client port number
    * non ephemeral port numbers: 0-1,023
    * ephemeral port numbers: 1,024-65,535
    * TCP and UDP ports can be any from 0-65,535
    * most services use non ephemeral ports
    * port numbers are for communication, not security
    * service port numbers need to be well known i.e. web servers should be on port 80/443 or else other things won't communicate properly
    * TCP port are not equivalent to UDP ports i.e. TCP/80 is not equal to UDP/80
### Common Ports and Protocols
* FTP (File Transfer Protocol): tcp/20-21
  * transfers files between systems, not specific to an OS, authenticates w/ username and passwrod, full featured functionality(list, add, delete, etc.)
* SSH (Secure Shell): tcp/22
  * text-based console communication with a remote device, encrypted communication link
* SFTP (Secure FTP): tcp/22
  * generic file transfer with encryption, same port as SSH because it uses the same encryption algorithm, as well as providing the same file system functionality
* Telnet: tcp/23
  * console access like SSH, but no encryption
* SMTP (Simple Mail Transfer Protocol): tcp/25, tcp/587
  * server to server email transfer, port 25 uses plaintext, port 587 uses TLS encryption, also used to send from a device to a mail server, IMAP/POP3 used for clients to receive mail
* DNS (Domain Name System): udp/53
  * converts FQDNs to IP addresses, larger data transfers may use tcp/53, critical resources, usually multiple servers
* DHCP (Dynamic Host Configuration Protocol): udp/67-68
  * automated configuration of IP address, subnet mask, and other options
  * requires a DHCP server
  * dynamic/pooled = IP addresses are leased in real time from a pool and must renew at set intervals
  * static/reserved = device is assigned the same IP by MAC address
  * port 67 = server, port 68 = client
* TFTP (Trivial FTP): udp/69
  * very simple file transfer, no authentication, useful when starting a system, transfer configuration files quickly and easily
* HTTP(S) (HyperText Transfer Protocol(Secure)): tcp/80, tcp/443
  * web server communication
  * port 80 is in the clear
  * port 443 is encrypted with TLS
* NTP (Network Time Protocol): udp/123
  * synchronize time across devices, critical for log files/authentication, timestamps/outage details, etc.
  * very accurate
  * control how often clocks are updated
* SNMP (Simple Network Management Protocol): udp/161, udp/162
  * gather stats from network devices
  * v1 in the clera
  * v2 data type enhancements, bulk transfers, in the cler
  * v3 message integrity, authentifation, encryption
  * SNMP traps send alerts from network devices over port 162
* LDAP (Lightweight Directory Access Protocol): tcp/389
  * store and retrieve information in a network directory
* LDAPS (LDAP Secure): tcp/636
  * LDAP over SSL i.e. with encryption
* SMB (Server Message Block): tcp/445
  * also called CIFS (Common Internet File System)
  * protocol used by Windows
  * integrated into the OS
  * access rights integration across systems, file share publishing, file locking, NetBIOS-less - direct SMB communication over TCP, file sharing and printer sharing and authentication to the network
* Syslog: udp/514
  * standard for message logging
  * consolidated logs from diverse devices, usually a central log collector, integrated into a SIEM
  * requires a lot of disk space to store logs
* MS-SQL (Microsoft SQL): tcp/1443
  * communicatae with database servers to store and query
* RDP (Remote Desktop Protocol): tcp/3389
  * share a desktop from a remote location
  * RDP services on many Windows devices but clients for most operating systems
* SIP (Session Initiation Protocol): tcp/5060-5061
  * VoIP signaling, setup and manage VoIP sessions
  * call, ring, play hold signal, hang up,
  * extended VoIP options include video conferencing, instant messaging, and file transfer
### IP (Internet Protocol) Types
* ICMP (Internet Control Message Protocol)
  * "text messaging" for network devices, carried by IP
  * not used for data transfer (TCP/UDP)
  * devices can request and reply to administrative requests or can alert when things are wrong
* GRE (Generic Routing Encapsulation)
  * encapsulate traffic inside of IP
  * 2 endpoints (usually VPNs) appear to be directly connected to each other
  * no built in encryption
* IPsec
  * security for OSI Layer 3
  * authentication and encryption for every packet
  * confidentiality and integrity
  * anti replay
  * very standardized
* IKE (Internet Key Exchange)
  * agree on encryption/decrption keys to build a Security Association (SA)
    * phase 1: use Diffie-Hellman to create a shared secret key, share over port udp/500 - ISAKMP (Internet Security Association And Key Management Protocol)
    * phase 2: coordinate ciphers and key sizes, negotiate on inobund and outbound SA for IPsec
    * transport mode is in the clear, tunnel mode is encrypted
  * AH (Authentication Header)
    * hash of the packet and a shared key which adds integrity
      * SHA1,SHA2, MD5 hashes
  * ESP (Encapsulating Security Payload)
    * encrypts the packet (3DFS, AES), adds a header, trailer, and Integrity Check value
### Network Traffic Trypes
* Unicast: one station sending info to another
  * web surfing, file transfers, does not scale for real time streaming media
* Multicast: one station sending info to many simultaneously
  * multimedia delivery, dynamic routing updates, very specialized
* Anycast: single desitnation has multiple paths to two or more endpoints
  * one to one of many
  * the closest device will receive the traffic
* Broadcast: send to everyone at the network all at once
  * limited scope, routing updates, ARP requests
