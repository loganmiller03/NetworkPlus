# 1.3 - Summarize cloud concepts and connectivity options

### Network functions virtualization (NFV)
* replace physical network devices with virtual versions
  * manage them from the hypervisor
*same functionality as the physical device (routing, switching, load balancing, firewalls, etc.)
* quickly and easily deploy network functions
* many different deployment options(VM, container, fault tolerance, etc.)

### Virtual Private Cloud (VPC)
* a pool of resources created in a public cloud
* common to create many VPCs for different app instances
* connect VPCs with a transit VPC Gateway/Internet Gateway
  * a "cloud router" connecting users and resources
* VPN NAT gateway
  * private cluod subnets connects to external resources
  * external resources cannot access the private cloud
### Cloud Connectivity Options
* Virtual Private Network (VPN)
  * site-to-site VPN through the internet
* Internet Gateway/VPC Gateway
  * connects users on the internet
* VPC NAT Gateway
  * network address translation
  * private cloud subnets connect to external resrouces, external resources cannot access the private cloud
* VPC endpoint/ Direct Connect
  * client communication between cloud providers
 ### Network security groups and lists
  * a firewall for the cloud control inbound/outbound traffic flows
  * Layer 4 port # - TCP/UDP port
  * Layer 3 address - IPv4/IPv6, CIDR block notation
  * List
    * assign a rule to an entire IP subnet
    * very broad - can be difficult to manage
    * nay need more granularity - not all devices need the same rules
  * Group
    * assign rules to specific virtual network interface cards (VNIC) i.e. based on MAC address
    * individual/specific devices
    * better control/granularity
 ### Cloud deployment models
 * Public: available to everyone over the internet
 * Private: your own virtualized data center
 * Hybrid
### Cloud service models
* Software as a Service (Saas)
  * on demand software
    * no local installation
    * someone else manages all data, updates, etc.
  * no development required
  * google mail, O365
* Infrastructure as a Service (IaaS)
  * also called HaaS (Hardware as a Service)
  * outsource your equipment and use your own software
  * you are responsible for management and security
  * data still out there like SaaS, but more under your control
  * web server providers
* Platform as a Service (Paas)
  * no servers, no software, no maintenance team
  * you handle development
  * you don't have direct control of data, people or infrastructure
  * SalesForce: create apps from what the platform provides you
 ### Scalability: can we handle increasing users, data, etc.?
 ### Elasticity: automatically adjust resources based on demand
 ### Multitenancy: multiple customers share physical resources
